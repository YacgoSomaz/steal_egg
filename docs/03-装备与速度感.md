# 03 · 装备体系、速度感与数值虚假化

> 对应第四轮试玩反馈：
> "能不能用特效给他来表达速度快慢呢？然后我觉得啊，数值可以虚假化，
> 还有提升不用那么线性，比如他是可以花钱买跑鞋、锻炼、装备什么的来提高他速度的"

---

## 一、速度感：不是把数字调大，是让画面真的变快

### 上一轮失败的真正原因

第三轮我把速度从 9 调到 90（×10），用户却说"还是没感觉"。
根因不是数值不够大，而是**同一轮里我做了四件互相抵消的事**：

| 我做的 | 效果 |
|---|---|
| 速度 ×10 | 想让它更快 |
| 世界尺度 ×3.25 | 跑道/间距同比放大 → 相对速度不变 |
| 相机拉远 ×6 | 画面里物体变小、移动变慢 |
| 模型放大 ×2.6 | 参照物变大 → 又抵消一次 |

净效果 ≈ 白涨。**数字涨了，画面没涨，玩家只信画面。**

### 现在的做法：固定参照物

速度感的唯一来源是**参照物经过的频率**。所以：

- **地面横向条纹（虚线）间距固定 5 单位，不随世界尺度缩放**
  - 速度 6 → 每秒穿过 1.2 条
  - 速度 63 → 每秒穿过 12.7 条
  - 差 10 倍，肉眼直接可见 —— 这是速度感的主来源
- **相机 FOV 72° → 90°** 随速度撑开（推背感）
- **相机补偿封顶 3.5**（原 6）、**模型放大系数 0.15**（原 0.35）
  → 补偿只用来防"看不清"，不再用来抵消速度
- **怪物腿部摆动频率挂钩速度**：`sin(t × (4 + speed × 0.55))`
  → 高阶怪不只是"更快"，是四条腿甩得更快

### 特效（`scripts/run/speed_fx.gd`）

| 特效 | 说明 |
|---|---|
| 速度线 | 64 条 CPUParticles3D，沿 −Z 拖尾，加色混合（Additive） |
| 尘土 | 40 粒，脚下扬起，慢速时几乎不可见 |
| 相机抖动 | 高速时轻微抖动，幅度随速度增长 |
| 玩家前倾 | `-clamp(speed/60, 0, 1) × 0.20` 弧度 |

强度统一由 `r = clamp(speed / 60, 0, 1.3)` 驱动，一个系数管全部。

**实现坑（Godot 4 CPU 粒子）**：`CPUParticles3D` 用的是**扁平属性**，
不是 `ParticleProcessMaterial`。写错名字会静默失效：

| 写错 | 正确 |
|---|---|
| `particle_flag_align_y_to_velocity` | `particle_flag_align_y` |
| `scale_min` | `scale_amount_min` |
| `billboard` | `billboard_mode` |
| （塞进 material） | `direction` / `initial_velocity_min` 是粒子系统本体的属性 |

## 二、数值虚假化：数字好看比数字正确重要

内部速度区间是 9 – 90（这是**物理正确**的：刚好让 T1–T10 的怪 6.0–63.5 有意义）。
但"我的速度 9"听起来毫无成就感。

**显示层统一乘 `DISPLAY_SPEED_SCALE = 3.6`，单位换成 km/h：**

| 内部速度 | 显示 | 称号 |
|---|---|---|
| 9 | 32 km/h | 步行 |
| 15 | 54 km/h | 慢跑 |
| 25 | 90 km/h | 狂奔 |
| 45 | 162 km/h | 疾驰 |
| 65 | 234 km/h | 音速 |
| 90 | 324 km/h | 超音速 |
| 120+ | 430+ | 无视物理 |

称号由 `GameState.speed_title()` 给出：
步行 → 慢跑 → 狂奔 → 疾驰 → 音速 → 超音速 → 无视物理

**原则**：所有物理判定用内部速度，所有 UI 用显示速度。
玩家永远看不到内部数字 —— 那是我们自己的账本。

## 三、四个速度来源：三种不同算法

不再是一条线性升级线。四种来源各有各的算法和定位：

### 1. 锻炼（乘法，后期主力）

```
速度 ×= 1.09 ^ speed_level
成本 = 40 × 1.62 ^ speed_level
上限 Lv30（×13.3）
```

指数增长，**越到后面越猛**。前期点一级只加 0.8，很不起眼；
后期一级能加 7。这是长期主线。

### 2. 跑鞋（加法，前期主力）

```
速度 += 2.5 × shoe_level
成本 = 80 × 1.70 ^ shoe_level
上限 Lv20（+50）
```

固定加成，**早期立竿见影**（基础速度才 9，加 2.5 就是 +28%）。
但到后期速度 90 时，+2.5 只有 +2.8%，自然被淘汰。

> **设计意图**：加法源早期猛、乘法源后期猛。
> 玩家一开始买鞋爽到，中期开始转向锻炼，两条曲线在 Lv8 左右交叉。
> 这比"一条线走到底"有意思得多。

### 3. 隐形披风（影响苏醒延迟，不是速度）

```
苏醒延迟 ×= 1 + 0.15 × gear_cloak
上限 Lv5（×1.75）
```

配合隐蔽等级：`延迟 = 阶位基础 × (1 + 0.09 × 隐蔽Lv) × (1 + 0.15 × 披风Lv)`
满配 ≈ ×4.9 —— 偷完蛋后有近 5 倍的时间跑路。

### 4. 喷气背包（开局爆发）

```
开局 2.5 秒内，速度 ×= 1 + 0.25 × gear_jet
上限 Lv5（×2.25）
```

只在**起跑阶段**生效。用途是：偷到蛋的瞬间拉开距离，
在怪物苏醒前冲出危险区。是一次性的战术资源，不是常驻速度。

### 惩罚：被抓

```
速度 ×= 0.97 ^ catch_count
上限叠加 20 层（×0.54）
治疗：花 150 × 1.25^catch_count 抹掉 3 层
```

和升级同一套乘法逻辑（用户明确要求："升级加百分之多少，被抓减百分之多少，
一直采用指数函数"）。

### 四源汇总公式

```
最终速度 = (9.0 + 2.5 × 鞋Lv) × 1.09^锻炼Lv × 0.97^被抓次数 × 喷气倍率
```

## 四、为什么这样"不线性"更好玩

| 线性升级 | 现在 |
|---|---|
| 每次升级体感一样 | 买鞋前期爽、锻炼后期爽、喷气救急、披风保命 |
| 只有"变强"一个维度 | 有爆发 / 常驻 / 容错 / 规避四种方向 |
| 决策 = 有钱就点 | 决策 = 这点钱买鞋还是攒着买披风 |
| 后期升级越来越无聊 | 锻炼指数越滚越大，每次都肉眼可见 |

**核心**：让玩家在"立刻变快"和"长期变快"之间做选择，
而不是无脑点同一个按钮。
