# 06 · 技术陷阱清单（改代码前必读）

> 这份清单里的每一条都**实际浪费过时间**。
> 有些会直接报错，有些是**静默失效**——后者更致命，因为你可能根本不知道自己写错了。

---

## 一、Godot 4 粒子系统：CPUParticles3D 是扁平属性

`CPUParticles3D` **不用** `ParticleProcessMaterial`。写错名字**不报错，直接失效**。

| ❌ 写错（GPU 版命名） | ✅ 正确（CPU 版） |
|---|---|
| `particle_flag_align_y_to_velocity` | `particle_flag_align_y` |
| `scale_min` | `scale_amount_min` |
| `billboard` | `billboard_mode` |
| （塞进 material 里） | `direction` / `initial_velocity_min` 是粒子系统**本体**的扁平属性 |

参考 `scripts/run/speed_fx.gd` 的写法。

## 二、GDScript 严格类型：推断不出来就报错

项目开了「警告当错误」，很多看起来正常的代码会被拦下。

### 典型场景

```gdscript
# ❌ 会推断成 Variant，被拦下
var pts := PackedVector2Array([Vector2.ZERO])
var x = wrapf(a, b, c)
var c = get_collider()
var s = get_tree().current_scene

# ✅ 显式声明
var x: float = wrapf(a, b, c)
var c: Node = get_collider() as Node
```

### `preload().instantiate()` 返回的是 Node

自定义方法**不能**直接调：

```gdscript
var c = preload("res://scenes/run/creature.tscn").instantiate()

c.setup(data)                    # ❌ 静态报错
c.call("setup", data)            # ✅

player.sneaking                  # ❌
bool(player.get("sneaking"))     # ✅
```

### 混类型数组取出来是 Variant

```gdscript
var spec = [[String, Callable]]   # 取 spec[1] 是 Variant

var cb: Callable = spec[1]        # ❌
var cb: Callable = spec[1] as Callable   # ✅
```

### JSON 解出来是 untyped Array

不能直接赋给 `Array[Dictionary]`，必须重建：

```gdscript
# SaveManager 里的 _to_dict_array()
func _to_dict_array(arr: Array) -> Array:
    var out: Array = []
    for e in arr:
        if e is Dictionary:
            out.append(e)
    return out
```

## 三、字符串：拼接与格式化

### 多行字符串不能用括号拼接

```gdscript
# ❌ 语法错误
note.text = (
    "第一行"
    "第二行"
)

# ✅ 用续行符 + 加号
note.text = "第一行" \
    + "第二行"
```

### 格式化参数个数必须严格对上

```gdscript
# ❌ 格式符与参数顺序/数量不匹配
_stat.text = "速度 %.1f（Lv%d…" % [display_speed, speed_title(...), ...]

# ✅ 逐项核对
_stat.text = "速度 %.0f km/h【%s】（锻炼 Lv%d，×%.2f）" % [
    display_speed, GameState.speed_title(display_speed), speed_level, mult
]
```

## 四、循环里的 lambda 捕获

```gdscript
# ❌ lambda 捕获循环变量不安全，所有按钮会绑到最后一个 i
for i in range(n):
    btn.pressed.connect(func(): _on_click(i))

# ✅ 用 bind
for i in range(n):
    btn.pressed.connect(_on_click.bind(i))
```

## 五、class_name 在命令行模式下不注册

```gdscript
class_name CreatureDB     # ❌ --headless 下报 "Identifier not declared"
```

**解决**：去掉 `class_name`，各调用方用 preload：

```gdscript
const CreatureDB := preload("res://scripts/data/creature_db.gd")
```

连带影响：静态函数返回值推断不出类型，调用处必须显式声明：

```gdscript
var d: Dictionary = CreatureDB.tier_data(tier)
```

## 六、3D 场景与朝向

### 相机必须显式设 rotation

正交/透视相机默认是**平视**的。做 2.5D 俯视/越肩必须手动设 pitch：

```gdscript
cam.rotation_degrees.x = -17    # 越肩视角
```

### 朝向公式（Godot 前向是 −Z）

```gdscript
rotation.y = atan2(-to.x, -to.z)
```

### CharacterBody3D 没碰撞体也能 move_and_slide

本作靠距离判定，不需要 `CollisionShape3D`。这不是 bug。

## 七、场景树与节点生命周期

### 动态生成的追兵必须 reparent

丢失蛋的怪物要一路追到撤离点，但 chunk 回收时会被一起删掉：

```gdscript
# creature.gd 的 on_egg_stolen() 里
reparent(get_tree().current_scene)   # 必须！否则追兵凭空消失
```

**不加这一行，"丢蛋的怪追到底"这套机制根本不成立。**

### chunk 长度可变后不能用索引定位

原来 `floor(z / 100)` 索引 chunk。世界尺度让 chunk 长度不再固定后，
必须改成**链表式按需追加**：

```gdscript
_chunks 数组 + _head_z，AHEAD=4 / BEHIND=2，按 z 范围回收
```

### `_ready` 执行顺序

脚本的 `_ready` 可能早于场景主逻辑。读运行时设好的值时用：

```gdscript
call_deferred("_late_init")
```

否则读到的是 `@export` 默认值。

---

### `--script` 模式不注册 autoload 全局标识符

```bash
Godot --headless --script res://tools/xxx.gd
```
这种模式下，脚本里 `extends SceneTree`，autoload **不会**注册成全局标识符。
任何引用 `GameEvents` / `GameState` / `SaveManager` 的脚本都会编译失败：

```
SCRIPT ERROR: Compile Error: Identifier not found: GameEvents
   at: GDScript::reload (res://scripts/run/creature.gd:64)
```

（有意思的是 autoload 本身**会**被实例化——你还是能看到存档加载的打印，
只是脚本里按名字引用不到。）

**对策**：自检脚本只测不依赖 autoload 的纯模块；
需要 autoload 的接线靠 `--main-scene` + headless 覆盖。

### `find_children` 的 `owned` 参数

```gdscript
root.find_children("*", "MeshInstance3D", true, true)    # ← 返回 0 个！
root.find_children("*", "MeshInstance3D", true, false)   # ✅
```

运行时 `add_child()` **不会设置 owner**，第四个参数传 `true` 会一个都找不到。
第一版建模自检就是这么报出"网格 0"的假象。

### `--jump` 不会重新生成怪物

`--jump 20000` 只把玩家传送过去，**怪物列表在传送之前就生成完了**。
所以不管跳多远，`--diag` 的阶位分布始终是 `{1..7}`，高阶代码根本没跑到。

要逐阶验证高阶内容，用 `--gallery N` 或 `tools/model_test.gd`。

## 八、性能

### 远处睡怪必须跳过物理

80 只怪全开 `_physics_process` 会掉帧：

```gdscript
if dist > 700:
    visible = false
    return    # 跳过 _physics_process
```

### 单局跑道全程常驻

`MAX_RUN_DIST = 4000`，**不回收**。
之前"往回走跑道消失"就是边跑边回收导致的。代价是内存，但 4000m 规模可接受。

## 九、数值设计陷阱（不是语法，但更贵）

### ⚠️ 补偿会抵消掉你的数值膨胀

**这是本项目最贵的一个坑，用户连着抱怨三轮。**

如果你想让游戏"感觉更快"，**不要同时**做这几件事：

| 动作 | 后果 |
|---|---|
| 速度 ×10 | 想更快 |
| 世界尺度 ×3.25 | 间距同比放大 → 相对速度不变 |
| 相机拉远 ×6 | 画面物体变小变慢 |
| 模型放大 ×2.6 | 参照物变大 → 又抵消 |

**净效果 ≈ 白涨。**

✅ 正确做法：**固定参照物**（地面虚线间距固定 5，不随世界尺度缩放），
相机补偿封顶（3.5），模型系数压低（0.15）。
补偿只用来防"看不清"，**不用来抵消速度**。

### 追击速度必须真的追得上

v1 里守卫追击 70，玩家跑 180 —— 玩家是守卫 2.57 倍，**永远跑得掉**。
"速度决定你跑不跑得过怪物"这条设计完全失效。

**调数值时先算一下：怪物追击速度 vs 玩家实际速度，谁快？**

### 等距层次 vs 等比层次

用户直接指出"你好像是等距的"。
**体感上，等比（×1.3/阶）比等差（+1.5/阶）膨胀感强得多。**
