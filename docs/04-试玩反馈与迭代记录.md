# 04 · 四轮真人试玩反馈与迭代记录

> **这份文档是本仓库最有价值的证据。**
>
> 它逐条记录了用户玩过之后说了什么、我改了什么、以及哪些改动是"看起来对其实翻车"的。
> 接手的 AI 请**重点看每条反馈后面标注的根因**——用户抱怨的往往不是表面那个问题。

---

## 总览

| 轮次 | 时间 | 用户核心抱怨 | 性质 |
|---|---|---|---|
| **1** | 首玩 | 视角不对 / 速度要指数 / **100% 被抓** / 怪速度没差别 | 1 个致命设计缺陷 |
| **2** | 二玩 | 还是不膨胀 / 层次等距 / 丢蛋的怪不追到底 | 数值 + 机制 |
| **3** | 三玩 | **还是**不膨胀 / **跑道消失** / 别出草鸡 | **补偿抵消** + 硬 bug |
| **4** | 四玩 | 用特效表达速度 / 数值可虚假化 / 提升别线性 | 体验层 |

### 一条贯穿始终的教训

**用户连着三轮说"感觉不到数值膨胀"。**

第一、二轮我都以为"那就是数值不够大"，于是继续把数字往上调。
**第三轮才找到真因：不是数值不够大，是我自己的补偿措施把涨的部分全抵消了。**

> **纸面平衡一定会翻车。必须让人玩，而且玩完要追问"你感觉到了吗"，
> 不能只看数字有没有涨。**

## 第一轮：首玩（4 条）

用户原话：
> "我刚刚玩了一下，不错不错，但是我希望视角更低一点……要看到远处的巨型生物吗？
> 所以我希望可以采用越肩视角？……他这个减速是永久给我减速了，我觉得还是不太合理，
> 他应该是当前给我的速度减少百分之多少，然后我升级的话，他应该是给我的速度加百分之多少，
> 我们一直采用这种指数函数的方式……我每次偷蛋都百分百被减速，你知道为什么吗？
> 因为我还没偷他就开始追我了……我觉得隐匿应该是我偷到蛋以后，他醒的时间，这个才对，
> 还有不同等级的怪物他的移动速度应该不一样"

### ① 越肩视角 + 要看到远处的巨型生物

**改了什么**
- 相机从「正交 + 50° 俯角」→ **透视 + 越肩**：offset `(1.6, 4.4, 8.2)`，pitch −17°，FOV 72
- 新增 `scripts/run/landmark.gd` + `scenes/run/landmark.tscn`：**远处巨型生物**
  - 不参与玩法，纯视觉地标
  - 永远在玩家前方 250 单位，两侧各一个（x = −62 / +70）
  - 体型 `k = 1 + tier*0.16`，压暗 0.3 + 雾 → 剪影感
  - 极慢呼吸 + 缓慢摇头
- 加 `WorldEnvironment`：天空 BG_COLOR + ambient + **fog density 0.0022**

> 这就是 v1 里"开局就要把宇宙龙摆在玩家眼前"这个诉求在 v2 的落地方式。

### ② 速度改成指数乘法堆叠 ★ 用户明确指定算法

**旧**：`9.0 × (1+0.05×Lv) × (1−penalty)` —— 线性加法
**新**：`9.0 × 1.07^Lv × 0.97^catch_count`

用户原话：
> "他应该是当前给我的速度减少百分之多少，然后我升级的话，他应该是给我的速度加百分之多少，
> 我们一直采用这种指数函数的方式"

配套：`speed_penalty`(float) → **`catch_count`(int)**，
治疗 = 抹掉 3 次记录，成本 `150 × 1.25^catch_count`

### ③ 隐蔽 = 苏醒延迟（不是感知范围）★ 致命缺陷修复

**用户自己诊断出来的**，而且诊断得很准：
> "我每次偷蛋都百分百被减速，你知道为什么吗？因为我还没偷他就开始追我了"

**根因**：两个设计叠在一起 = 必被抓
1. **proximity wake** —— 靠近就吵醒怪物
2. 偷蛋读条期间玩家 **frozen 不能动**

**修复**
- **删掉 proximity wake**：睡着的怪不会被路过吵醒，**只有蛋被动了才醒**
- 隐蔽唯一职责 = 苏醒延迟：`tier_wake × (1 + 0.09 × 隐蔽Lv)`
- 偷蛋读条固定 1.2s（不再受隐蔽影响，职责单一）
- WAKING 状态：zZz 变红色 "!" + 后一半时间抖动 → 给玩家"快跑"的信号
- 蹲行保留意义：偷蛋波及半径 12 → 6

> 💡 **这是整个项目里最重要的一次修复。**
> 我推算了一整天都没发现这个缺陷，用户玩一局就找到了。

### ④ 不同等级怪速度要拉开

- 拉开跨度，并在**怪头顶加标签** `T4 火蜥 13.2`，沉睡灰白 / 追击变红
- HUD 也显示当前阶怪的速度做对比

> 不标出来玩家根本不知道怪有多快，也就感受不到"我变快了"。

## 第二轮：还是不膨胀（4 条）

### ① 数值不够膨胀 + 升级收益不明显

用户原话：**"宇宙龙才 18，我升两级他就追不上我了"**

**根因**：怪速度**等差** +1.5（6.5→18，仅 3.3 倍），玩家 `1.07^Lv`（Lv11 就通吃）

**改**
- 怪速度 **×1.30/阶**（6.0→63.5，10.6 倍）、体型 ×1.21、产出 ×2.65
- 玩家 **×1.09/Lv**，MAX_LEVEL → 30
- 每深入一阶约需升 2.6 级，T10 要 Lv21 才跑得过（原 Lv11）

### ② 首次出现的层次不能等距

用户直接指出：**"你好像是等距的"**

**改**：`RUN_TIER_GAPS` 查表，区间非等距递增
```
[250, 600, 1200, 2200, 3800, 6300, 10000, 16000]
```
低阶换得快，高阶越跑越漫长。

### ③ 丢失蛋的怪应该一直追到撤离点

**改**
- `creature.gd` 加 `_lost_egg` 标志 → 无视 CHASE_TIMEOUT / GIVE_UP_DIST
- **必须 reparent 到 `current_scene`**：否则玩家跑远、chunk 被回收时追兵凭空消失
  （在 `on_egg_stolen()` 里 reparent —— **这是这套机制能成立的关键**）
- 抢回蛋后 `_lost_egg = false` 才回巢；距离 >1500 才彻底放弃
- 回巢时若 `_home` 距离 >800（chunk 已回收）直接 `queue_free`
- 被波及吵醒的怪仍按 25s / `max(70, 速度×8)` 放弃

### ④ 速度膨胀带来的硬约束

速度涨 10 倍后，跑道宽 26 完全不够用——角色一秒穿过好几条街，画面失控。

**三件套**（⚠️ 这三件后来被证明是第三轮 bug 的根源，见下）：
1. **世界尺度** `world_scale(tier) = 1 + (tier-1)×0.25`（T10 ×3.25）
2. **相机随速度拉远** `zoom = clamp(1 + 速度/14, 1, 6)`
3. **角色模型同步放大** `1 + (zoom-1)×0.35`

连带改动：chunk 长度不再固定 → **不能再用 `floor(z/100)` 索引**，
改成链表式按需追加（`_chunks` 数组 + `_head_z`，AHEAD=4 / BEHIND=2，按 z 范围回收）

## 第三轮：还是不膨胀 + 跑道消失（★ 最惨痛的一轮）

用户原话：
> "不行，现在我还是没感觉到数值膨胀的感觉，无论是我的速度还是动物的移动追击速度，
> 还有刚才我往回走的时候，跑道直接消失了，不显示，
> 还有里面的这些数值关系，我觉得要改一改了……每次玩家回来以后，
> 根据他的速度直接给他上更高级的门了，也别出什么草鸡了，谁还要草鸡这些呢？
> 还拖慢大家的节奏……可以查询一下资料，找一些灵感，此外，数值关系你还是再好好研究一下"

### ⚠️ 【最重要教训】速度感被我自己的补偿抵消了

**这轮的真正发现**：用户抱怨"数值涨了但没感觉"，
根因不是数值不够大，**是我第二轮做的三件套 + 速度提升，四件事互相抵消**：

| 我做的 | 效果 |
|---|---|
| 速度 ×10 | 想让它更快 |
| 世界尺度 ×3.25 | 跑道/间距同比放大 → **相对速度不变** |
| 相机拉远 ×6 | 画面里物体变小、移动变慢 |
| 模型放大 ×2.6 | 参照物变大 → **又抵消一次** |

**净效果 ≈ 白涨。数字涨了，画面没涨，而玩家只信画面。**

**修法**
- **地面横向条纹**（ImmediateMesh）间距**固定 5 单位，不随 world_scale 缩放**
  ← **速度感的主来源**
  - 速度 6 → 每秒 1.2 条
  - 速度 63 → 每秒 12.7 条，差 10 倍
- **FOV 随速度撑开** 72→90（推背感）
- **相机补偿封顶 3.5**（原 6）
- **模型补偿系数 0.15**（原 0.35）
- 怪物腿部摆动频率挂钩速度 `sin(t*(4+speed*0.55))`

### 跑道消失 bug（硬伤）

用户："往回走的时候，跑道直接消失了"

**原因**：chunk 边跑边回收（BEHIND 只留 400 单位），玩家折返时路已经没了

**修**：**单局跑道封顶 `MAX_RUN_DIST = 4000`，全程常驻不回收**，尽头建一堵墙 + "折返"标牌

配套性能措施：远处睡怪 `visible=false` 且跳过 `_physics_process`（>700 单位），
否则 80 只怪掉帧

### 起始阶位系统（去掉草鸡）

用户：**"别出什么草鸡了，谁还要草鸡这些呢？还拖慢大家的节奏"**

```gdscript
start_tier_for(speed) = 速度能压过的最高阶（speed >= tier_speed * 1.05）
```
- 速度 9 → T2；速度 34（Lv14）→ **T7 开门**；满速 → T10
- 距离→阶位改为**相对**：`tier_at(run_distance, start_tier)`
- `GameState.start_tier` + `refresh_start_tier()`，farm 和 main 的 `_ready` 都调

**螺旋**：速度↑ → 门更深 → 蛋更值钱 → 产钱更多 → 速度↑

### 参考研究：《疯狂动物园》(Rodeo Stampede)

用户推荐后查证，其核心：
- 骑乘动物有耐心条
- **跑得越远，遇到的动物越稀有**
- 驯服后进天空动物园产金币
- 升级栖息地让后续跑更轻松

→ 本质就是**正反馈螺旋**，我们的起始阶位系统就是它的对应物。

## 第四轮：特效 + 虚假化 + 非线性提升

用户原话：
> "我在想，能不能用特效给他来表达速度快慢呢？然后我觉得啊，数值可以虚假化，
> 还有提升不用那么线性，比如他是可以花钱买跑鞋、锻炼、装备什么的来提高他速度的"

### ① 特效表达速度

新增 `scripts/run/speed_fx.gd` + `speed_fx.tscn`：
- **速度线** 64 条（沿 −Z 拖尾，加色混合）
- **尘土** 40 粒（脚底扬起）
- **相机 FOV** 72→90 + 高速抖动
- **玩家前倾** `-clamp(speed/60, 0, 1) × 0.20`

强度统一由 `r = clamp(speed/60, 0, 1.3)` 驱动，一个系数管全部。

详见 [`03-装备与速度感.md`](03-装备与速度感.md)。

### ② 数值虚假化

内部 9–90 → 显示 **×3.6 换成 km/h**（32–324 km/h）+ 称号
（步行 / 慢跑 / 狂奔 / 疾驰 / 音速 / 超音速 / 无视物理）

### ③ 四个速度来源，三种算法

| 来源 | 算法 | 定位 |
|---|---|---|
| 锻炼 | 乘 `×1.09^Lv` | 后期主力 |
| 跑鞋 | 加 `+2.5/级` | 前期立竿见影 |
| 披风 | 苏醒延迟 `+15%/级` | 保命 |
| 喷气 | 开局 2.5s `+25%/级` | 拉开距离 |

**设计意图**：加法源早期猛、乘法源后期猛，两条曲线在 Lv8 附近交叉。
让玩家在"立刻变快"和"长期变快"之间做选择，而不是无脑点同一个按钮。

## 反馈模式总结（给接手 AI）

用户的反馈有个明显规律：**他描述的是症状，根因通常在别处。**

| 用户说的（症状） | 真正的根因 |
|---|---|
| "百分百被抓" | proximity wake + 读条 freezing 叠加 |
| "数值不够膨胀" | 数字够大了，但**画面被补偿抵消** |
| "层次是等距的" | 字面意思，确实是等距 |
| "往回走跑道消失" | chunk 回收（字面意思） |
| "别出草鸡" | 低阶内容拖节奏，要跳过 |

**所以：接到反馈先问"为什么会有这个症状"，再动手。**
